## 构建

使用当前依赖支持的 Node：`^22.22.2 || ^24.15.0 || >=26`；优先与部署环境一致的 Node 24。不能把 Windows 原生依赖包复制到 Linux。构建环境运行 `npm ci`，生产主机只接收对应平台成品。

```sh
node --version
npm ci
npm run test:release
npm test
npm run lint
npm run build:release -- --output-dir build/releases/release-001 --source-revision SOURCE_COMMIT
npm run verify:release -- --release-dir build/releases/release-001 --port 3317 --report build/releases/release-001-smoke.json
```

`SOURCE_COMMIT` 应替换为被构建的真实提交 ID；有未提交修订时必须明确标记，不能冒充已提交版本。构建默认使用独立 `.next-release`；拒绝使用主项目 `.next`。构建过程还会创建同盘的临时书库与 TEMP/TMP，结束后只清理已核验的本次临时目录，不访问正式 `data`。Next 可能自动在 `tsconfig.json` 添加该构建目录的类型 include，开发提交前应审阅这部分生成差异。

单个脚本只负责一种职责：

- `scripts/build-release.mjs`：检查 Node，生成私有 worker，再走已验证的 Webpack 构建路径并装配发布。
- `scripts/release-traces.mjs`：读取 Next NFT 清单，拒绝未知越界路径，过滤构建机数据，补齐外部 EPUB 子进程的实际生产依赖闭包与依赖许可证。
- `scripts/package-release.mjs`：只装配已有构建，不重新编译；排他创建目标目录，拒绝覆盖旧版本。
- `scripts/release-manifest.mjs`：按路径排序并记录每个文件的 SHA-256 和逻辑字节，验证缺失、篡改、多余文件、危险路径及必要资源。
- `scripts/start-release.mjs`：校验清单与平台，强制指定发布目录外的绝对数据路径，然后启动同进程的 Next 服务。
- `scripts/smoke-release.mjs`：复制成品到系统临时目录再运行，不能从原项目或其父目录借用依赖。

`package:release` 可单独使用，参数与构建命令相同。目标目录必须不存在；失败目录保留 `.incomplete` 标记供诊断，不能作为正式版本启动，不会递归覆盖或清空用户目录。

## 发布白名单

包内为 Next standalone 的运行依赖闭包、完整 `public`、对应构建目录的 `static`、显式追踪的私有 MOBI/UMD worker、EPUB 子进程脚本与许可证，以及两个只依赖 Node 内置模块的启动/校验脚本。

注意：EPUB 的 `jsdom` 是生产依赖；PDF.js 使用动态加载，必须携带 Node worker 和对应平台原生依赖。不能因静态引用搜索未覆盖子进程就删除它们。

Next 的 `.nft.json` 是构建证据，不是运行资源，因其中可能含构建机路径，不进入发布包。Windows 自动复制缺失时，按 Next 输出文档允许的方式消费 NFT 清单补齐文件；其他未知的项目外追踪路径直接报错，不将其静默归类成可删缓存。

不复制正式 `data`、`.env*`、应用 `src`、`.git`、历史验证目录或 Next 开发/缓存目录；依赖自身的 `src` 可能是运行入口，不能全局按同名目录删除。校验清单自身不参与自身哈希；清单的 `totalBytes` 是被枚举内容字节数，实际目录还包括清单文件本身，压缩包大小另计。

## 独立运行与回滚

将目标平台发布目录放入独立且不可覆盖的版本目录。启动时设置：

- `JUDU_DATA_DIR`：现有正式书库的绝对路径，不在本次发布目录内。当前服务器可继续指向原项目正式 `data`，不搬书库。
- `JUDU_APP_ORIGIN`：实际 HTTPS 入口，保持既有 Caddy 认证及 HTTPS。
- `HOSTNAME=127.0.0.1`、`PORT=3000`：由现有反向代理接入，不扩大公网暴露面。

然后使用当前 Node 的绝对路径启动发布目录内的 `start-release.mjs`。生产包不执行 `npm ci`、`next build` 或启动时安装解析依赖。不得把密钥放进发布清单、提交消息或部署脚本。

每次升级先在独立端口与独立数据目录自测，保留旧发布目录和一致性数据备份，再由运维切换进程的工作目录及启动入口。回滚只切换旧程序目录，仍使用同一个显式正式数据路径。不要替换/删除运行中的构建目录；不能通过直接复制写入中的 SQLite 主文件来冒充完整备份，应使用 backup API 或停止写入后复制完整数据。

本阶段只复用既有数据库迁移。未来引入不可逆 schema 变更时，必须额外制定数据恢复策略，不能仅凭旧程序目录声称可回滚。

## 验收证据

`verify:release` 会先验证清单，再确认端口空闲，复制发布目录至系统临时目录，使用新的临时书库启动。测试进程不继承 `NODE_PATH`、预加载脚本、真实模型密钥或正式数据配置。

自动检查：

- 首页、书库、Next 静态文件、Foliate、PDF worker 与字体返回正常。
- 实际 HTTP 导入 TXT、Markdown、EPUB、PDF、MOBI、FB2、FBZ、CBZ 自造或仓库许可夹具。
- 下载原件与输入逐字节哈希一致，标注可保存并读回；跨站来源依然被拒绝。
- UMD 候选 worker 实际 IPC 解析通过，但 HTTP 导入仍按现有边界返回 415；不扩大产品支持承诺。
- 将相同版本的两个不可覆盖程序目录切换后回切，书库与标注仍使用同一份外部测试数据并可读；这只证明目录切换流程，不是跨 schema 降级证明。
- 停止服务后重新绑定同一端口，证明临时端口确实释放；删除本次已校验的临时 app/data。

这不是浏览器原版布局、付费模型或全格式复杂书籍矩阵的替代验收。Agent 工具协议、导图撤销、引用定位与流式状态由现有测试回归覆盖；正式平台/真实模型行为必须分别记录，不能把 HTTP 成功等同于端到端体验通过。

本地交付仍按项目约定：隔离验证成功并释放端口后，主项目使用 `3000`、默认 `.next`、正式 `data`，确认首页和书库 API 正常。原版首章超时遵循 `AGENTS.md` 的环境确认和用户接管流程，不改变渲染运输、shadow root、依赖行为或安全策略绕过验证。
