# 来源卡渐进展示与渠道分组（2026-09-24）

## 用户确认与范围
- 用户确认主项目能够显示，并提供真实截图，要求更优雅的渐进展示、分点及渠道区分。
- 本轮优化来源展示，不更改模型回答正文，不替用户改写原文，不引入网络搜索或整书后台建库。

## 交互层级
- 选文默认一行预览，显示段落数量和字数。
- 多段选文展开后先显示编号片段列表，首批 3 段；每段独立折叠，再按需加载后续 3 段。
- 单段短选文不增加多余层级；长原文先展示 220 字，可进一步展开完整内容，全文区域最大高度 280px。
- 原有换行和明确编号用于分点排版；片段拼接仍逐字等于原文，定位传递完整原始锚点。
- 检索总览展开后分别显示关键词、语义、补充阅读渠道；各组独立折叠，来源列表同样分批显示。
- 查询按条目展示；耗时、缓存、Token 等技术信息放进“执行详情”，隐私说明另行折叠。
- 双路命中明确标识，顶部参考总数按 sourceId 去重。历史数据没有 channels 时独立展示，不根据 hybrid 或相似度猜渠道，也不将未知归属说成未入选。

## 数据变化
- BookRetrieval 的融合候选记录真实命中 channels，并写入提供给 Agent 的来源对象。
- 工具审计、历史 API、SSE 回放保留 channels；read_source 不继承成新的关键词/语义命中。
- 未迁移或重建正式向量；已有消息、选文与标注原样保留。
