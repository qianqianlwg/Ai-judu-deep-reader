# Agent 并行检索与 pgvector 清理（2026-09-24）

## 交付范围
- 删除未接通的 PostgreSQL/pgvector 运行时、迁移、旧外部 embedding 入参以及 pg / @types/pg 依赖；不删除 SQLite 正式数据或已建向量。
- 统一书内搜索 API 与 Agent 的检索服务 `src/lib/book-retrieval.ts`。
- `search_book` 接收 query、最多两个 additionalQueries、可选 mode（auto / keyword / semantic / hybrid）、chapterId、limit；模型根据问题需要主动调用，不强制每条消息检索。
- 自动/混合模式并行关键词与语义，最多六路；按 RRF 融合、段落去重。自动模式支持空格关键词组覆盖排序，精确 keyword 保持字面短语语义。
- 每轮最多六个真实查询嵌入请求，成功查询向量有 10 分钟 / 128 条缓存；同轮同取消域的并发相同查询合并。失败、取消不写缓存；账号与模型 profile 隔离。
- 真实 usage 单独记录到每路报告；未知用量不猜测。失败支路显式降级，强制 semantic 无可用支路不能伪装成功。
- 来源绑定当前版本，最终回读重新验证正文、章节与偏移；保留来源注册、read_source 和逐字引文核验。
- 设置中可以关闭 AI 自动语义检索；默认在已配置并且本书索引完整时允许。查询会发往配置的向量服务；模型不能自行建库或上传整书。
- 对话回复前显示默认折叠的检索卡，展开后显示查询、各路候选数量/耗时/缓存/usage/失败原因、提供给模型的原文及定位按钮。取消不显示为成功，当前与历史尝试分离。
- 历史 API 和 SSE 回放只保留合法检索报告及经过版本过滤的来源。失败报告不能放宽对任意错误正文的隐藏。

## 设计决策
- 向量生成 API 与向量存储是两层；继续使用现有 SQLite 本地持久向量，不迁移正式索引。
- 组合根显式装配查询嵌入会话和检索服务；业务工具不调用本机 HTTP。
- 先提供可靠的异步工具查询，不引入整书后台建库任务、Redis 或额外数据库。
- 不将前端 bookSearch 快照直接当可信证据；Agent 通过服务器工具读取并注册真实来源。
- 进度与原文详情属于工具结果，不泄露隐藏推理；不使用相似度百分比暗示正确率。
