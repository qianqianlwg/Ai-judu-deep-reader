## 范围与决策

- 去掉“精读／原版”切换；有原件且支持原版的格式只进入原版阅读器。
- 保留 AI 句读、导读、搜索、朗读、知识库、笔记、标注、收藏、历史和阅读位置。纯文本和未保存原件的历史书籍仍可读，不删除原文投影或旧版数据。
- 原版渲染此前已使用 Foliate。本次让服务端 EPUB 元数据、spine、EPUB3 nav 和 NCX 解析也复用同一固定上游，而不是整体替换应用。
- 对比了 Koodo Reader、Foliate 和 epub.js 的官方仓库。选择可嵌入的 Foliate-js，避免搬入完整阅读应用后重写现有 AI、来源校验和标注体系。Foliate 应用与 foliate-js 引擎是不同仓库，不混用 Star 数。

## 导入边界

`foliate-import.ts` 显式装配 `scripts/epub/foliate-import-worker.mjs`：

1. 原有 ZIP 安全预检继续执行，不取消压缩大小、解压大小、CRC、路径、条目数量及脚本/资源安全限制。
2. 子进程只创建 XML DOM，禁用书内脚本执行和资源网络加载；限制输入 64 MiB、堆 512 MiB、时间 30 秒、输出 128 MiB、目录 32 层/5000 项。
3. 元数据、原生目录、spine 由上游解析。保留 OPF 原始 href，原文投影仅用于可核验的 AI/search/annotation 来源，不取代原书排版。
4. 字面百分号和 URI 编码路径使用精确寻址优先；不递归解码，不模糊猜测文件。缺失正文、无效协议、目录解析失败都报错，不跳过失败伪造导入成功。
5. jsdom 是生产依赖；父进程以 `require.resolve` 提供构建跟踪锚点，再用 Node 原生 createRequire 定位真实磁盘路径，避免将 Turbopack 虚拟模块 ID 传给子进程。依赖跟踪检查覆盖 jsdom 及其传递依赖；可选 canvas 不参与此 XML 解析。
6. 子进程提前退出时等待 close 收集 stderr，避免 EPIPE 覆盖真正引擎诊断。

旧 npm `epub` 暂时仅保留给既有封面提取路径，主动 EPUB 导入不再使用它。两本真实书的封面 API 已验证 200 image/webp；不为清理依赖而破坏封面。

## 目录与旧版兼容

- “未命名章节”主要来自把 spine 的正文分片当目录。界面现在使用书内真实的层级目录，同一文件内多个 fragment 目录项完整保留，并交给 Foliate 原生 goTo(href) 跳转。
- 没有真实目录时明确提示并提供文件顺序导航，不虚构章节名。
- 重复 ID 只取消对应的歧义应用锚点映射并记录诊断，不丢弃正文，不修改原生导航。
- `epub_navigation_cache` 是原件指纹绑定的派生缓存。已有书籍首次读取自动补建；不重新导入、不覆盖原件、不修改段落 ID、文本、哈希、标注或旧版本。
- 恢复、重试与跨书切换继续隔离 session；旧目录跳转的异步结果或错误不能回写新版本。
