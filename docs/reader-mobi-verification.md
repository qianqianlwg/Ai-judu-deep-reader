## 更正 2026-09-18 的临时结论

此前原型把同一个合成 MOBI6 文件分别命名为 `.mobi`、`.azw`、`.azw3`，只能证明扩展名分发和保存流程，不能证明 KF8/AZW3 内容可解析。该原型还存在目录标题用子串猜测、首记录预检不完整及主线程同步解析的风险。

2026-09-20 已撤回未经完整验收的生产 adapter、上传白名单、存储白名单和 UI 格式宣传；API 对这三类文件返回明确 415“正在验收，尚未开放导入”，不写书籍/章节/原件。保留候选研究模块与测试，不删除任何既有用户数据。完整 MOBI/AZW/KF8、原版资源和定位的阶段目标没有取消，也没有将“拒绝导入”当作格式交付。

## 当前可核验证据

### 容器预检（应用自有代码）

- 识别 PDB BOOK/MOBI、严格递增记录目录和当前 record 内边界。
- 按真实头版本识别 MOBI6/7 与 KF8，解析有界 EXTH，复核双格式 BOUNDARY/次头。
- 两个 PalmDOC 头均检查加密；DRM 字段不是仅凭文件后缀推断，不进行解密。
- 限制声明的正文/记录/头部数量和大小；这些预检不能代替下游实际解压/内存预算。

### 可终止的候选解析进程

- `mobi-parser.ts` 不再在 Next Web 主进程调用第三方同步解压；由独立 Node 子进程完成候选解析。
- 父进程拥有截止时间和 AbortSignal，实际终止同步死循环；收到 IPC 也必须等进程 close，随后才清理本次私有目录。
- 输入快照在首次 await 前复制；IPC 通过显式类型守卫、章节唯一 ID 和累计输出上限复核。
- 子进程不继承模型密钥或 NODE_OPTIONS，Node 文件权限只允许读依赖/worker及读写本次临时目录。
- V8 old-space 192 MiB 是堆预算，**不是 RSS、ArrayBuffer、磁盘或网络的完整 OS 沙箱**；不能据此宣称所有资源攻击都已解决。
- 子 agent 发现父进程旧 HTML 正则可被 64 KB 未闭合标签阻塞 2.5–6.9 秒；已将全部 HTML 解析/清洗放入 worker，使用固定开发依赖 `parse5@8.0.1`，父进程只验证有界的纯文本段落数组。该真实多记录恶意输入回归保留，不能用延长超时替代修复。
- 目录标题通过真实 `resolveHref` 解算，不再用 `href.includes(id)` 猜章节；正文与标题同文也不删除。
- MOBI 文本候选直接读公开 spine，避免为了提取文字写图片；KF8 原版资源保真、持久资源模型仍未完成。

## 2026-09-20 原始字节来源协议 v2（内部候选，未开放导入）

本批将“唯一 selector 命中”与“精确原始来源”分开，旧 `mobi-layout-untrusted-v1` 不再作为精确定位证据接受。

- 固定 vendor 新增 `source-byte-ranges` 补丁：MOBI 保存裁剪 head/body 前的章节字节与 pagebreak 后的真实 fileStart；KF8 在重建 skeleton/fragment 时同步记录 fid、片段字节区间与输出位置。片段内再次插入会拆分映射，不重置后半段原始 offset。
- `filepos`/`fid:off` 严格解析后，先转为重建章节字节，再通过 UTF-8 边界索引转为源码 UTF-16 偏移，最后按 parse5 的源码位置定位 body 子节点。重复文本、重复 ID 和没有 ID 的段落不通过猜测下一个元素定位。
- HTML 实体、CRLF、代理对必须有完整边界；标签属性内部、隐藏/脚本区域、SVG/MathML、正文根容器及越界位置保持 unresolved。已知排除区之外不推断外部 CSS 可见性。

## 2026-09-20 正文投影、资源身份与v3目标复核

本批解决上一批四个固定样本中10个内部目标未定位的问题，没有通过放宽“同文即同源”来获得通过。

- 根因：原始章节是完整document，而解析器输出是body片段。把片段当完整document解析会吞掉首部空白；原始document解析又可能把body外尾空白合并到末文本。这使相同正文的节点数量和路径不同。
- 新 `projectMobiDocument` 通过固定parse5的真实节点/关闭事件获取原字符串的UTF16窗口，body严格等于原字符串切片，不trim、不重新序列化。布局生成和来源索引共享该窗口，正文节点统一使用真实body上下文的fragment解析。MOBI首/中/末章、仅开/闭body、引号内大于号和脚本/注释伪标签均有用例。
- 投影预算包含输入、DOM、模板、深度及大量被忽略token。只有解析器接受的容器关闭才能成为边界；会丢实质正文、frameset或跨边界head重排的输入明确失败。内部Parser hook依赖固定parse5行为，升级须重新验收。
- 独立审计发现同文段落交换ID、图片交换src仍能通过旧的无属性签名。现在签名包括语义属性；资源地址必须由本次解析器实际记录的别名关联到已捕获资源，并先按同一受控语义转换生成预期正文，再与实际布局比对。不会忽略属性，也不会猜资源文件名。
- MOBI旧 `recindex`、`mediarecindex`、`filepos` 改为真实HTML属性投影，支持图片、音视频与链接；不把注释/脚本/模板中的字面标签当资源。新旧属性冲突、非法整数及未知来源明确失败或保持未定位，不静默替换正文。
