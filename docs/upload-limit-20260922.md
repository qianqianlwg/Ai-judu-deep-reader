# 300 MB上传限制及明确超限提示（2026-09-22）

## 根因和修复
- 导入接口原上限100MiB，但Next.js proxy默认仅缓冲10MiB，较大的multipart被截断后被错误归类为“上传表单不完整或已损坏”。
- 共享限制模块：文件上限300*1024*1024=314572800字节（沿用二进制计量，界面显示300 MB）；multipart请求上限301MiB；proxy缓冲302MiB。
- 使用当前Next.js本地文档中的 experimental.proxyClientMaxBodySize，不使用已废弃的middlewareClientMaxBodySize。
- 阅读器和独立书架均在选文件后预检大小，超限显示实际文件大小与300MB上限，不发起上传；非JSON 413也显示大小提示。
- 代理预检Content-Length，接口再次预检并逐块计算真实上传字节，无长度或不可信长度仍受限；超过请求或文件上限返回413、upload_too_large和maxFileBytes。
- 真正不完整multipart维持400，文案为“上传未完成或表单格式不正确”，不再据此认定书籍文件损坏。
- 保留既有来源校验、格式解析及解压安全限制；没有修改渲染方案或放开跨站访问。
