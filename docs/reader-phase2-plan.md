## 2. P0 实施前已确认原因（历史记录，已修复多片段契约）

截图中的选文跨越多个正文段落和双栏排版。浏览器可以产生有效 Range，但应用尚未把它表达为多段来源。

- `src/lib/epub-source-map.ts` 的 `selectionFromEpubRange` 在 `touched.length !== 1` 时返回 null，明确拒绝多段选文。
- `src/components/epub-reader.tsx` 将该结果显示为“请选择同一正文段落，或切回精读”。
- `ReadingSelection`、`ReadingAnchor` 和句读请求目前使用单个 paragraphId/start/end；仅删除前端限制不足以修复保存、重试和回跳。
- 手动阅读标注已有 anchors 数组及服务端逐段校验，可以复用原则，但 AI 句读链路还未具备同等能力。
- `src/lib/reading-detail.ts` 另有单次 10–1000 字限制。截图的准确字数尚未测量，不能把此次错误直接归因为超过长度。
- 截图右侧的“未配置 AI 服务”是另一独立问题；选区修复不等于已经配置模型。

这不是 foliate 无法选文，也不需要为了通过工具验证而改变 blob 运输或 closed shadow root。

## 3. P0：修复当前选区问题

### 3.1 有版本的多片段选区契约

- 选区保存书籍版本、原文件身份、按阅读顺序排列的片段、完整文本及原版定位信息。
- 每片段保存 paragraphId、UTF-16 start/end、精确原文和校验信息；两端可为半段，中间段落完整保留。
- EPUB CFI/resource locator 负责原版导航，canonical 段落偏移负责文本核验，不能只靠视觉坐标或文本搜索找第一个相似结果。
- 单段选区是多片段契约的特例；旧历史、旧标注和知识卡片可在读取时兼容，不批量重写旧来源。
- 新格式契约应版本化；数据库具体增量迁移在实施时按受影响表确定，不把方案当作既定表结构。

### 3.2 EPUB 选区提取和界面

- 支持同一文档内跨段、跨栏、反向拖选，保持逻辑阅读顺序，不按屏幕左右位置生硬拼接。
- 同段跨页片段去重并保持连续；跨文档/章节不能假设浏览器有一个完整 Range，提供明确的“继续选取下一页”合并交互。
- 统一处理前后空白、排版换行及已识别的脚注标记，建立可追溯偏移映射；不任意删除数字、标点或真实脚注内容。
- 对尚未建入正文索引的标题/脚注正文，评估独立来源块补充索引，不冒充相邻正文。首个 P0 验收门槛是截图中的连续正文跨段选区；尚未支持的内容类型单独说明。
- 浮动工具栏展示段落数、字数和选文预览；不能静默只取第一段或截取一部分。
- 新选区无效、选区清空、切书/切版本时清除旧状态，防止实际提交上一次选文。
- 无法证实来源时提供具体原因，不用一个笼统提示掩盖所有失败，也不伪造精确来源。

### 3.3 打通完整句读链路

同步覆盖选文状态、请求构建、普通/流式 API、服务端验证、Agent 工具、会话快照、取消/重试、知识保存和原文回跳。

- 服务端从同一 edition 逐片段核验范围、文本/哈希、顺序、连续性及覆盖，拒绝跨书混入、乱序、重叠、缺段和篡改。
- 展示文本与发送文本使用同一份已核验选区快照；段落分隔符是明确的组装规则，不假装属于段内偏移。
- 重试使用首次提交的快照，不受用户之后划选影响。
- 知识卡片和历史消息保存整个来源集合；回跳定位起始处并高亮全部相关片段，不只指向第一段。
- 复用手动标注多锚点校验理念，保持原版/精读的来源一致。

### 3.4 选文硬上限（用户已明确：2026-09-18）

- 一次最多选中 1000 字，跨段、跨栏、跨页时按整个选区合计，不是每个片段各有 1000 字额度。保留现有最少 10 字的句读规则。
- 前端在拖选、反向拖选、键盘扩选和跨页继续选取等入口限制可见选区，不允许继续扩展到超过 1000 字；到达上限时提示“最多选择 1000 字”。工具栏显示“已选 n / 1000 字”。
- 最终可见高亮、原文预览、来源片段和提交文本必须一致；不能让界面显示选中了更多内容，却在请求里偷偷只发送前 1000 字。达到上限不会自动发起句读。
- 提交前再次检查；任何仍超过 1000 字的选文都拒绝句读，提示缩小选区，不自动截断后提交。
- 普通/流式 API、重试等所有分析入口均执行服务端上限校验；超过 1000 字直接拒绝，不调用模型、不生成拆分任务。
- 取消此前的“分段句读”建议，不增加批量分析、自动拆分或额外请求。
- 前后端使用统一字数统计口径，沿用现有 Unicode 字符计数规则；来源锚点偏移仍按 UTF-16，不把字符数量与锚点偏移混为一谈。
- 模型未配置时明确引导配置，不把问题归咎于选区，也不代填密钥或擅自发起付费请求。

### 3.5 P0 验收门槛

- 用户提供 EPUB 的同类双栏、多段选区在 10–1000 字内能够形成完整来源并进入句读流程。
- 同段/多段、正反拖选、脚注标记、重复文本、表情/非 BMP 字符、跨页片段、选区清空均有定向测试。
- 验证 999、1000、1001 字边界以及 Unicode 字符：可见选区最多 1000 字；1000 字可正常句读，1001 字请求被前后端拒绝且不调用模型。跨段/跨页合计上限一致，不自动拆分，不静默截断提交。
- 服务端拒绝伪造来源；保存、重试、刷新、主题切换、字号变化后仍能正确回跳。
- 旧书架、旧会话、旧标注和知识卡片可读；不要求为了本次修复重导入全库。
- API/流式与持久化用受控测试模型验证；真实模型验收需有效配置，不能把 mock 通过说成真实模型已经通过。

## 4. 第二阶段 A：PDF 原版阅读

沿用既定的“原文件表现层 + AI 文本索引层”，不以 PDF 控件替换现有会话、知识和书库。

### A1. 原版展示

- PDF.js Canvas 展示原页，TextLayer 提供真实文字选取，AnnotationLayer 提供受安全策略约束的链接/批注表现。
- 页码跳转、缩放、旋转、目录（文件存在时）、阅读位置恢复；大文件按需渲染，限制页面/画布缓存并释放资源。
- PDF 文件自带的链接/批注不等于应用内阅读标注；两者来源和持久化分开处理。
- 不为迎合主题色默认反转图片和公式；原版页与应用外壳的外观策略明确区分。

### A2. 页文本与来源映射

- 提取时保留页号、文本项、变换/位置与规范化偏移，而不是仅拼接整个文档的纯文本。
- 复用 P0 多片段契约，增加 PDF 页内文本/坐标定位；缩放和旋转不改变语义来源身份。
- 处理断词、连字、换行、多栏和重复页眉页脚；每种规范化有偏移追溯，不把 getTextContent 的排列直接当成所有 PDF 的正确阅读顺序。
- 支持跨页选文、原版/精读切换、句读/手动标注以及知识卡片回跳。
- 旧 PDF 有原件时增量建立映射并维护旧锚点；无法唯一衔接时明确说明或生成新版本，不悄悄改写旧段落 ID。
- 没有原件的历史导入继续精读，用户补充原件后再建立原版能力，不虚构可恢复的原版页。

### A3. 能力边界

- 纯扫描页可原版查看；没有文字层时明确提示不能直接文字句读。
- OCR、图片理解及公式结构理解属于独立能力，不以“Canvas 已显示/能框选”冒充已经实现。
- 可复制的公式文本也不等于完整数学语义；混合扫描/文字 PDF 按页面反馈能力。
- 不执行 PDF 内嵌脚本，不绕过文件加密或 DRM；外部链接遵循明确交互及安全策略。

## 5. 第二阶段 B：额外格式

这是既有阶段文档列出的目标范围，不表示当前代码已支持，也不承诺仅改扩展名即可支持。

1. FB2/FBZ：已实现解析、资源、分级目录、正文索引和 locator/CFI 的代码/API闭环；真实原版浏览器验收仍待既有环境确认，详见 reader-fb2-verification.md。
2. CBZ：已实现图片原件导入、归档校验、页码/缩放/方向/位置恢复和无文字能力边界；详见 reader-cbz-verification.md。
3. MOBI/AZW/AZW3：按真实编码/容器分别验收，仅针对可合法读取、未受 DRM 保护的样本；不能把一种样本通过当作全部格式通过。2026-09-20 已有严格容器预检、独立候选进程和真实上游样本探针；固定KF8样本的文字、资源和locator候选已通过，未开放生产导入；后续仍需安全资源图、净化后的canonical/DOM投影、完整原版版式与导入精读闭环，详见 reader-mobi-verification.md。
4. UMD → EPUB：单独确认转换实现、许可、编码和资源保真；保存原件、转换版本和对应关系，不覆盖原文件。当前限定文字profile已有候选解析、EPUB生成、来源投影、原件/派生物双份持久化与转换版UI内部验证；公开导入、完整文字/漫画/混合内容矩阵及实机来源回跳仍未完成，仍在原目标范围内。
5. TXT/Markdown：保留现有精读链路，复用多段选文改进，不为统一界面强制转为 EPUB。

每类格式先确认解析器能力和许可，再实现并以真实样本验收；若依赖不满足，单独报告，不以格式列表替代支持证明。
